# 用 AI 管理远程服务器

这份文档教你怎么用 WebClaw 容器 + AI CLI Studio 管理远程 Linux 服务器：装软件、改配置、查日志、管 Docker。

照着做完，你会得到这样的体验：打开一个会话，输入「把 nginx 装上，端口改成 8080」，AI 自己连到服务器上装、改配置、验证、重载。

---

## 一、这是什么

我们在**你自己电脑的 Docker 里**跑一个 WebClaw 容器，当作「运维基地」。AI Studio 装在这个容器里，AI 也在这个容器里跑。

每台被管理的服务器，跟这个基地之间接**两条线**：

```
      你的 Mac
  ┌─────────────────────────────┐
  │  WebClaw 容器（运维基地）      │
  │                             │
  │   AI Studio + Claude Code   │
  │        │          │         │
  │      文件        命令        │
  │        │          │         │
  └────────┼──────────┼─────────┘
           │          │
      sshfs 挂载    ssh 命令
           │          │
           ↓          ↓
  ┌─────────────────────────────┐
  │      远程服务器 prod-web      │
  │                             │
  │  /etc/nginx/nginx.conf ← 改  │
  │  apt install nginx     ← 跑  │
  └─────────────────────────────┘
```

**为什么要两条线？** 因为它们各干各的事，谁也替代不了谁：

- **挂载**能让 AI 像改本地文件一样改服务器上的配置文件，但它**不能执行命令**。
- **ssh** 能执行命令（`apt`、`systemctl`、`docker`），但改文件要拼 `sed -i` 那种命令，容易出错。

两条线用**同一把密钥、同一份配置**，配一次就都通了，你不用管两次。

**为什么 AI 要跑在容器里，不是直接跑在 Mac 上？**
因为挂载需要一个叫 FUSE 的东西。macOS 上装它（macFUSE）要重启进恢复模式、降低系统安全级别，很折腾；Linux 容器里就是一条 `apt install` 的事。而 AI 必须和挂载在同一台机器上才能读到那些文件，所以 AI 跟着进容器。

## 二、准备（只做一次）

### 1. 重建镜像

挂载工具 `sshfs` 是加在**基础镜像**里的，所以两层都要重新构建：

```bash
cd webclaw-docker

# 第一步：构建基础镜像（含 sshfs），十几分钟
docker build -f Dockerfile.base -t webclaw_base:local .

# 第二步：在它之上构建正式镜像，1 分钟左右
docker build -t land007/webclaw:latest \
    --build-arg WEBCLAW_BASE_IMAGE=webclaw_base \
    --build-arg WEBCLAW_BASE_VERSION=local .
```

> **第二条的两个 `--build-arg` 不能省。** `Dockerfile` 默认是从 `ghcr.io/land007/webclaw_base:latest` 继承的，不指定的话它会去远端拉一个**没有 sshfs 的旧镜像**，你会发现挂载死活用不了，而且没有任何报错提示原因。
>
> 基础镜像只有改了 `Dockerfile.base` 时才需要重建。平时改配置、改脚本只跑第二条。

### 2. 重建容器

`docker-compose.yml` 里加了两项容器权限（`/dev/fuse` 和 `SYS_ADMIN`），**这是挂载能工作的前提**。已经在跑的旧容器不会自动获得这些权限，必须重建：

```bash
docker compose up -d --force-recreate
```

> `--force-recreate` 不能省。不加的话 Docker 看容器还活着就不动它，你的新权限不会生效，后面挂载会失败并报 `fuse: device not found`。
>
> 数据不会丢：所有目录（`~/.ssh`、`~/servers`、项目、配置）都在 Docker 命名卷里，重建容器不影响。

### 3. 进入基地

浏览器打开：

```
http://localhost:20000
```

用 `.env` 里配的账号密码登录，进去就是一个 Linux 桌面。

后面所有命令，除非特别说明，**都是在这个容器里执行的**（可以用桌面上的终端，或者在 Mac 上 `docker exec -it webclaw bash`）。

### 4. 安装 AI Studio

AI Studio 不是预装的，是「按需安装」的应用，第一次要装一下。

在容器桌面上打开 **Launchpad（应用中心）**，在 **AI** 分组里找到 **AI CLI Studio**，点安装。装完桌面上会出现图标。

命令行装也行：

```bash
sudo DISABLE_ZENITY=1 /opt/install-webcode-ai-studio.sh
```

> 需要 `sudo`，因为它要 `dpkg -i` 装 deb 包。`DISABLE_ZENITY=1` 是跳过图形确认框，在纯终端里必须加。
>
> 装过一次之后它在容器卷里持久化，重建容器不用重装。

## 三、接入第一台服务器

一条命令：

```bash
add-server prod-web 203.0.113.10 root
```

三个参数分别是：

| 参数 | 含义 | 说明 |
|---|---|---|
| `prod-web` | 你给这台机器起的名字 | 之后一直用这个名字称呼它，比如 `ssh prod-web`。只能用字母数字和 `. _ -` |
| `203.0.113.10` | 服务器 IP 或域名 | |
| `root` | 登录用户 | 可省略，默认 `root` |

端口不是 22 的话，加第四个参数：`add-server prod-web 203.0.113.10 root 2222`

### 会发生什么

脚本分五步，屏幕上会依次打出来：

**`[1/5] 配置 ssh`**
往 `~/.ssh/config` 写一段配置，给这台机器登记名字、地址、用户。如果你还没有 SSH 密钥，它会自动生成一把（`~/.ssh/id_ed25519`）。

> 这里还配了一个叫 **ControlMaster** 的东西，作用是「一次连接反复使用」。AI 每执行一条命令都是一次新的 ssh 调用，没有它每次都要重新建立连接（约 300 毫秒），有了之后是 5 毫秒。几百条命令下来，差别就是「能用」和「慢到不想用」。

**`[2/5] 安装公钥（这是唯一一次需要输密码）`**
这一步会提示你输服务器的 root 密码。**整个流程只有这里需要密码。**

输完之后，你的公钥被写进服务器，以后再也不用密码了。密码不会被保存在任何地方。

> 如果这台机器之前就配过免密，会直接显示「已经免密，跳过」。

**`[3/5] 建工作目录`**
建一个 `~/servers/prod-web/` 目录，并 `git init`。

> `git init` 不是为了版本管理，是为了让 AI Studio 的目录扫描能认出它 —— AI Studio 把「含有 `.git` 的目录」当作一个工程。

**`[4/5] 生成 mount.sh / CLAUDE.md / settings.json`**
生成三个文件（详见第九节），其中 `CLAUDE.md` 会自动填入探测到的服务器系统版本。

**`[5/5] 挂载`**
把服务器的根目录挂到 `/mnt/prod-web`。成功的话会打印「已挂载」。

### 确认接入成功

```bash
ssh prod-web hostname          # 应该直接返回主机名，不问密码
cat /mnt/prod-web/etc/hostname # 应该能读到同样的内容
```

两条都通过，这台机器就接好了。

### 加更多机器

重复执行就行，一台一条：

```bash
add-server prod-db 203.0.113.11 root
add-server staging-1 203.0.113.20 root
```

## 四、在 AI Studio 里开始用

### 1. 添加扫描目录

打开 AI Studio → 设置 → 工作区目录，把 `~/servers` 加进去。

加完之后，你接入的每台服务器都会作为一个「工程」出现在左侧列表里。

### 2. 新建会话

在 `prod-web` 上新建一个会话。

> ⚠️ **一定要关掉「创建 worktree」开关。**
>
> worktree 是给写代码的工程用的（给每个 AI 会话开一个独立分支目录，避免互相打架）。服务器运维目录没有分支概念，开着它会创建失败或产生莫名其妙的目录。

### 3. 试一句

会话里输入：

```
这台服务器是什么系统？装了 nginx 吗？
```

正常的话，你会看到 AI 执行 `ssh prod-web ...` 之类的命令，而不是直接跑本地命令。

## 五、日常怎么用

直接用大白话说你想干什么就行。下面是四个典型例子，以及 AI 在背后会走哪条线。

### 例 1：装软件

> 把 nginx 装上，启动并设置开机自启

AI 会走 **ssh 线**：
```
ssh prod-web 'apt update && apt install -y nginx'
ssh prod-web 'systemctl enable --now nginx'
ssh prod-web 'systemctl status nginx'
```

### 例 2：改配置

> nginx 默认端口改成 8080

AI 会**两条线配合**：
1. 用 Edit 工具改 `/mnt/prod-web/etc/nginx/sites-enabled/default`（挂载线，像改本地文件）
2. 用 ssh 验证并重载（命令线）：`ssh prod-web 'nginx -t && systemctl reload nginx'`

这就是挂载的价值所在 —— 改配置文件不用拼 `sed` 命令。

### 例 3：查日志排障

> 网站 502 了，帮我看看什么原因

AI 会走 **ssh 线**查日志：
```
ssh prod-web 'tail -100 /var/log/nginx/error.log'
ssh prod-web 'systemctl status php-fpm'
ssh prod-web 'ss -lntp | head -30'
```

### 例 4：批量看一批机器

> 看一下 prod-web、prod-db、staging-1 的磁盘占用

AI 会写个循环：
```bash
for h in prod-web prod-db staging-1; do
  echo "=== $h ==="; ssh $h 'df -h /'
done
```

不需要专门的批量功能，ControlMaster 让这个循环跑得很快。

## 六、两条线的规矩

理解这三条，你就知道 AI 什么时候在干什么，出问题也能一眼看出哪里不对。

| 要做的事 | 走哪条线 | 长什么样 |
|---|---|---|
| 读 / 改**已知路径的单个文件** | 挂载 | `/mnt/prod-web/etc/nginx/nginx.conf` |
| 执行任何命令 | ssh | `ssh prod-web 'systemctl restart nginx'` |
| **搜索、遍历目录** | **ssh** | `ssh prod-web 'grep -r xxx /etc'` |

### 路径换算只有一条规则

> **服务器上的路径，前面加 `/mnt/<名字>`，就是基地里的路径。**

```
服务器： /etc/nginx/nginx.conf
基地：   /mnt/prod-web/etc/nginx/nginx.conf
```

因为我们挂的是服务器的根目录 `/`，所以这条规则对所有路径都成立，不用记第二套。

### 为什么搜索必须走 ssh

在挂载目录上跑 `grep -r` 或 `find`，每读一个文件、每查一次文件属性都是一次网络往返。搜一遍 `/etc` 可能是几千次往返，慢到无法忍受。

而 `ssh prod-web 'grep -r xxx /etc'` 是在服务器**本地**搜完，只把结果传回来，快几百倍。

这条规则已经写进每台机器的 `CLAUDE.md` 里了，AI 一般会遵守。如果你发现它在挂载目录里搜、卡住不动，打断它，提醒一句「用 ssh 搜」。

### 别搞错机器

不加 `ssh prod-web` 前缀的命令，跑在**基地容器**上，不是服务器上。

如果 AI 直接跑 `apt install nginx`（没有 ssh 前缀），它装的是容器自己，服务器上什么都没发生。看到这种情况打断它。

## 七、权限弹窗

### 为什么会弹

AI 每执行一条命令前，Claude Code 都会弹窗问你「允许执行吗」。这是它自带的保护，**也是目前挡在你生产服务器前面最主要的一道关**。

不要嫌烦就整个关掉。

### 怎么少弹一点

把常用的**只读**命令加进白名单。编辑 `~/servers/prod-web/.claude/settings.json`：

```json
{
  "permissions": {
    "allow": [
      "Bash(~/servers/prod-web/mount.sh)",
      "Bash(ssh prod-web cat *)",
      "Bash(ssh prod-web grep *)",
      "Bash(ssh prod-web ls *)",
      "Bash(ssh prod-web systemctl status *)",
      "Bash(ssh prod-web journalctl *)",
      "Bash(ssh prod-web docker ps*)",
      "Bash(ssh prod-web docker logs *)"
    ],
    "deny": [
      "Bash(rm -rf /mnt/*)",
      "Bash(rm -r /mnt/*)",
      "Bash(mv /mnt/*)",
      "Bash(chmod -R *)",
      "Bash(chown -R *)",
      "Bash(mkfs*)",
      "Bash(dd *)",
      "Bash(ssh prod-web rm -rf *)",
      "Bash(ssh prod-web mkfs*)",
      "Bash(ssh prod-web dd *)"
    ]
  }
}
```

`add-server` 已经帮你生成了这个文件，上面就是它的完整内容（`prod-web` 换成你的机器名）。你可以按需要往 `allow` 里加自己常用的只读命令。

> 注意 `deny` 里为什么两种写法都有：`Bash(rm -rf /mnt/*)` 挡的是通过**挂载**删文件，`Bash(ssh prod-web rm -rf *)` 挡的是通过 **ssh** 删文件。同一件事有两条路能做到，规则必须两边都堵。

改完要**重开会话**才生效。

### ⚠️ 一条铁律

**`allow` 列表里绝对不要出现通配写法**，比如：

```json
"Bash(ssh prod-web *)"     ← 绝对不行
"Bash(ssh *)"              ← 绝对不行
"Bash(*)"                  ← 绝对不行
```

只要加了其中任何一条，AI 在这台服务器上做**任何事**都不会再问你了 —— 包括删库。这是唯一一个能让整套保护瞬间归零的操作。

### 关于 deny 规则的诚实说明

`deny` 是**前缀匹配**，它挡得住：

```bash
rm -rf /mnt/prod-web/etc        ← 被拦
```

但挡不住换个写法的同一件事：

```bash
cd /mnt/prod-web && rm -rf etc  ← 溜过去了
```

所以 `deny` 的作用是「降低手滑的概率」，**不是「保证安全」**。真正兜底的是「没被 allow 的命令都要你点确认」这条默认行为。

### 想给某台机器上硬保险

如果某台生产机你完全不想让它被写入，编辑 `~/servers/<名字>/mount.sh`，在 `sshfs` 的参数里加一行 `-o ro`：

```bash
sshfs "prod-web:/" "/mnt/prod-web" \
    -o ro \
    -o reconnect \
    ...
```

然后重新挂载：

```bash
fusermount -u /mnt/prod-web && ~/servers/prod-web/mount.sh
```

这是**内核层面**的只读，AI 用任何写法都绕不过去。代价是改配置只能走 ssh 了。

## 八、出问题怎么办

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 访问 `/mnt/xxx` 卡住不动，Ctrl-C 也停不下来 | 网络中断导致挂载变「僵尸」 | `fusermount -u /mnt/xxx && ~/servers/xxx/mount.sh` |
| 容器重启后 `/mnt/xxx` 是空的 | 挂载不会自动恢复（设计如此，按需挂载） | `~/servers/xxx/mount.sh` |
| 挂载报 `fuse: device not found` | 容器没有 FUSE 权限 | 回到第二节第 2 步，`docker compose up -d --force-recreate` |
| `ssh xxx` 还要输密码 | 公钥没装成功 | 重跑 `add-server xxx <IP> root`，它会跳过已完成的步骤 |
| AI 执行命令特别慢（每条好几百毫秒） | 连接复用没生效 | `ls ~/.ssh/cm/` 看有没有 socket 文件。没有的话检查 `~/.ssh/cm` 目录是否存在且权限是 700 |
| AI 直接跑 `apt install`，没加 ssh 前缀 | 它没读到或忽略了规则 | 打断它，提醒「要用 ssh prod-web 执行」。反复出现的话在 `CLAUDE.md` 末尾补一条更醒目的提醒 |
| AI 在挂载目录里 `grep -r`，卡住 | 同上 | 打断，提醒「搜索要用 ssh」 |
| 改了 `settings.json` 但还在弹窗 | 会话没重开 | 关掉会话重新建一个 |

### 查看某台机器现在挂没挂

```bash
mountpoint /mnt/prod-web
```

### 全部卸载重来

```bash
fusermount -u /mnt/prod-web
~/servers/prod-web/mount.sh
```

## 九、给每台机器补充信息（重要）

`add-server` 生成的 `~/servers/<名字>/CLAUDE.md` 最后有两行等你填：

```markdown
## 这台机器

- 地址: 203.0.113.10:22 (root)
- OS: Ubuntu 22.04.4 LTS
- 跑着: <填:nginx / postgres / docker ...>
- 注意: <填:只有你知道的坑,比如「8080 端口被 X 占着不要动」>
```

**这两行是这套东西长期价值的来源。** 系统版本 AI 自己能探测，但下面这些它永远猜不到：

- 这台机器跑着哪些关键服务，哪个不能随便重启
- 哪个端口被什么占着
- 上次踩过什么坑
- 有没有什么手工改过、不在包管理里的东西
- 备份在哪、重启窗口是什么时候

每次你发现 AI 因为不知道某件事而做错了，就把那件事补进这两行。用得越久，它越懂你的服务器。

例子：

```markdown
- 跑着: nginx（反代）、postgres 14、docker（3个容器：api/worker/redis）
- 注意:
  - 8080 被老版本 java 服务占着，那是财务系统，别动
  - postgres 不要用 systemctl restart，要先 `pg_ctl stop -m fast`
  - /data 是单独挂载的云盘，别往 / 里写大文件，根分区只有 20G
  - 每周日 3:00 有备份任务，那个时间段别重启
```

## 十、文件都在哪

### 每台服务器一个目录

`~/servers/<名字>/`：

| 文件 | 作用 | 你要改吗 |
|---|---|---|
| `CLAUDE.md` | 告诉 AI 这台机器怎么操作，以及机器本身的信息 | **要**，补最后两行 |
| `mount.sh` | 挂载脚本，可以反复跑，已挂载会立刻退出 | 一般不用，除非要加 `-o ro` |
| `.claude/settings.json` | 权限规则 | 按需加只读命令到 `allow` |
| `.git/` | 让 AI Studio 认出这是个工程 | 不用管 |

这个目录也可以放这台机器的运维笔记、部署脚本、配置备份 —— 它是个 git 仓库，随手 commit 就有历史。

### 其他位置

| 路径 | 作用 |
|---|---|
| `~/.ssh/config` | 所有服务器的连接配置，`add-server` 自动维护 |
| `~/.ssh/id_ed25519` | 你的私钥，所有服务器共用一把 |
| `~/.ssh/cm/` | 连接复用的 socket，自动生成，可以随时删 |
| `/mnt/<名字>/` | 挂载点，映射服务器的根目录 |

### 容器重建会丢东西吗

不会。`~/servers`、`~/.ssh` 都在 Docker 命名卷里（`servers-data`、`ssh-data`），容器重建、镜像升级都不受影响。

只有 `/mnt/` 下的挂载是临时的，重启后跑一下 `mount.sh` 就回来了。

## 附：命令速查

```bash
# 接入一台服务器（唯一一次输密码）
add-server <名字> <IP> [用户] [端口]

# 挂载 / 重新挂载
~/servers/<名字>/mount.sh

# 卸载卡死的挂载
fusermount -u /mnt/<名字>

# 看挂没挂
mountpoint /mnt/<名字>

# 手工连过去
ssh <名字>

# 确认连接复用生效（应该有 socket 文件）
ls ~/.ssh/cm/
```
