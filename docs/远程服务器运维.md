# 用 AI 管理远程服务器

这份文档教你怎么用 WebClaw 容器 + AI CLI Studio 管理远程 Linux 服务器：装软件、改配置、查日志、管 Docker。

照着做完，体验是这样的：打开一个会话，输入「把 nginx 装上，端口改成 8080」，AI 自己连到服务器上装、改配置、验证、重载。

---

## 一、这是什么

在**你自己电脑的 Docker 里**跑一个 WebClaw 容器，当作「运维基地」。AI Studio 装在这个容器里，AI 也在这个容器里跑。

每台被管理的服务器，跟这个基地之间接**两条线**：

```
      你的 Mac
  ┌─────────────────────────────┐
  │  WebClaw 容器（运维基地）      │
  │                             │
  │   AI Studio + Claude Code   │
  │        │          │         │
  │      文件        命令        │
  │        │          │         │
  └────────┼──────────┼─────────┘
           │          │
      sshfs 挂载    ssh 命令
           │          │
           ↓          ↓
  ┌─────────────────────────────┐
  │      远程服务器 prod-web      │
  │                             │
  │  /etc/nginx/nginx.conf ← 改  │
  │  apt install nginx     ← 跑  │
  └─────────────────────────────┘
```

**为什么要两条线？** 它们各干各的事，谁也替代不了谁：

- **挂载**让 AI 像改本地文件一样改服务器上的配置文件，但它**不能执行命令**。
- **ssh** 能执行命令（`apt`、`systemctl`、`docker`），但改文件要拼 `sed -i` 那种命令，容易出错。

两条线用**同一把密钥、同一份配置**，接入时一次配好。

**为什么 AI 要跑在容器里，不是直接跑在 Mac 上？**
挂载需要 FUSE。macOS 上装 macFUSE 要重启进恢复模式、降低系统安全级别，很折腾；Linux 容器里就是一条 `apt install`。而 AI 必须和挂载在同一台机器上才能读到那些文件，所以 AI 跟着进容器。

> 也可以在 Mac 上原生跑 AI Studio。那种情况下面板会自动检测到没有 sshfs，服务器以**「仅命令」模式**接入：ssh 照常可用，只是没有文件挂载，改配置改走 `ssh host "sed -i ..."`。面板顶部会有提示，生成的 CLAUDE.md 也会自动换成不含挂载路径的版本。

## 二、准备（只做一次）

### 1. 重建镜像

挂载工具 `sshfs` 加在**基础镜像**里，所以两层都要重新构建：

```bash
cd webclaw-docker

# 第一步：构建基础镜像（含 sshfs），十几分钟
docker build -f Dockerfile.base -t webclaw_base:local .

# 第二步：在它之上构建正式镜像，1 分钟左右
docker build -t land007/webclaw:latest \
    --build-arg WEBCLAW_BASE_IMAGE=webclaw_base \
    --build-arg WEBCLAW_BASE_VERSION=local .
```

> **第二条的两个 `--build-arg` 不能省。** `Dockerfile` 默认从 `ghcr.io/land007/webclaw_base:latest` 继承，不指定的话会去远端拉一个**没有 sshfs 的旧镜像**，你会发现挂载死活用不了，而且没有任何报错提示原因。
>
> 基础镜像只有改了 `Dockerfile.base` 时才需要重建。平时只跑第二条。

### 2. 重建容器

`docker-compose.yml` 里加了两项容器权限（`/dev/fuse` 和 `SYS_ADMIN`），**这是挂载能工作的前提**。已经在跑的旧容器不会自动获得，必须重建：

```bash
docker compose up -d --force-recreate
```

> `--force-recreate` 不能省。不加的话 Docker 看容器还活着就不动它，新权限不会生效，后面挂载会失败并报 `fuse: device not found`。
>
> 数据不会丢：所有目录都在 Docker 命名卷里，重建容器不影响。

### 3. 进入基地

浏览器打开 `http://localhost:20000`，用 `.env` 里配的账号密码登录，进去是一个 Linux 桌面。

### 4. 安装 AI Studio

AI Studio 不是预装的，是「按需安装」的应用，第一次要装一下。

在容器桌面上打开 **Launchpad（应用中心）**，在 **AI** 分组里找到 **AI CLI Studio**，点安装。

命令行装也行：

```bash
sudo DISABLE_ZENITY=1 /opt/install-webcode-ai-studio.sh
```

> 需要 `sudo`（要 `dpkg -i` 装 deb 包），`DISABLE_ZENITY=1` 是跳过图形确认框。
>
> 装过一次之后在容器卷里持久化，重建容器不用重装。

## 三、接入第一台服务器

全部在图形界面里完成。

### 1. 打开面板

AI Studio 里打开**「远程服务器」**面板（面板顶部的导航图标，或设置里的入口）。

### 2. 点「添加服务器」，填表

| 字段 | 说明 |
|---|---|
| **名字** | 你给这台机器起的名字，比如 `prod-web`。之后一直用它称呼这台机器（`ssh prod-web`）。只能用字母、数字、点、下划线、连字符 |
| **地址** | IP 或域名 |
| **端口** | 默认 22 |
| **用户** | 默认 root |
| **跳板机** | 可选。需要经过堡垒机才能到达时填堡垒机的 ssh 别名，留空表示直连 |
| **标签** | 可选，逗号分隔。20 台以上时用来分组，比如 `生产, web` |
| **root 密码** | **只用这一次**，用来把公钥装进服务器，不会保存在任何地方 |

### 3. 点「接入」，看进度

面板会逐步显示六个步骤：

1. **准备 SSH 密钥** — 没有就生成一把（`~/.ai-studio/ssh/id_ed25519`）
2. **安装公钥** — 唯一用到密码的一步。装完之后再也不需要密码
3. **探测系统信息** — 自动读出发行版版本
4. **创建工作目录** — `~/servers/<名字>/`
5. **生成 CLAUDE.md 与权限规则** — 告诉 AI 这台机器怎么操作
6. **挂载远程目录** — 挂到 `/mnt/<名字>`（没有 sshfs 时这一步显示「跳过」）

全绿就接好了。这台机器会自动出现在左侧的工程列表里。

> 如果第 2 步失败，最常见的两个原因是密码错误、或者服务器 `sshd_config` 里禁用了密码登录（`PasswordAuthentication no`）。面板会给出具体提示。

### 4. 补上机器说明（很重要）

点这台机器的**「编辑」**，在**备注**里写下只有你知道的事：

```
跑着 nginx（反代）、postgres 14、docker（3个容器：api/worker/redis）

8080 被老版本 java 服务占着，那是财务系统，别动
postgres 不要用 systemctl restart，要先 pg_ctl stop -m fast
/data 是单独挂载的云盘，根分区只有 20G，别往 / 里写大文件
每周日 3:00 有备份任务，那个时间段别重启
```

保存后这段会自动写进 `CLAUDE.md`，AI 每次开会话都能看到。

**这是整套东西长期价值的来源。** 系统版本 AI 自己能探测，但上面这些它永远猜不到。每次发现 AI 因为不知道某件事做错了，就把那件事补进来。用得越久越好用。

## 四、开始用

在面板里点这台机器的**「开会话」**，选一个 CLI（Claude Code / Codex / …），就能开始了。

> worktree 开关对服务器工程会自动隐藏并关闭 —— 那是给代码工程用的（给每个 AI 会话开独立分支目录），服务器运维目录没有分支概念。

先试一句：

```
这台服务器是什么系统？装了 nginx 吗？
```

正常的话你会看到 AI 执行 `ssh prod-web ...`，而不是本地命令。

### 四个典型例子

**装软件**

> 把 nginx 装上，启动并设置开机自启

AI 走 **ssh 线**：`ssh prod-web 'apt install -y nginx'` → `systemctl enable --now nginx`

**改配置**

> nginx 默认端口改成 8080

**两条线配合**：用 Edit 工具改 `/mnt/prod-web/etc/nginx/sites-enabled/default`（挂载线），再 `ssh prod-web 'nginx -t && systemctl reload nginx'`（命令线）。这就是挂载的价值 —— 改配置不用拼 `sed`。

**查日志排障**

> 网站 502 了，帮我看看什么原因

AI 走 **ssh 线**查 `error.log`、`systemctl status`、`ss -lntp`。

**批量看一批机器**

> 看一下 prod-web、prod-db、staging-1 的磁盘占用

AI 写个 shell 循环。ControlMaster 连接复用让这个循环很快，不需要专门的批量功能。

## 五、两条线的规矩

理解这三条，你就知道 AI 什么时候在干什么。

| 要做的事 | 走哪条线 | 长什么样 |
|---|---|---|
| 读 / 改**已知路径的单个文件** | 挂载 | `/mnt/prod-web/etc/nginx/nginx.conf` |
| 执行任何命令 | ssh | `ssh prod-web 'systemctl restart nginx'` |
| **搜索、遍历目录** | **ssh** | `ssh prod-web 'grep -r xxx /etc'` |

### 路径换算只有一条规则

> **服务器上的路径，前面加 `/mnt/<名字>`，就是基地里的路径。**

因为挂的是服务器的根目录 `/`，这条规则对所有路径都成立，不用记第二套。

### 为什么搜索必须走 ssh

在挂载目录上跑 `grep -r` 或 `find`，每读一个文件、每查一次属性都是一次网络往返。搜一遍 `/etc` 可能是几千次，慢到无法忍受。而 `ssh prod-web 'grep -r ...'` 在服务器**本地**搜完只传结果回来，快几百倍。

这条已经写进每台机器的 `CLAUDE.md`。如果发现 AI 在挂载目录里搜、卡住不动，打断它提醒一句。

## 六、权限弹窗

### 为什么会弹

AI 每执行一条命令前，Claude Code 都会问你。这是它自带的保护，**也是挡在生产服务器前面最主要的一道关**。不要嫌烦就整个关掉。

### 已经帮你挡掉的

每台机器的 `~/servers/<名字>/.claude/settings.json` 里自动生成了规则。其中一条特别值得说：

```json
"deny": [
  "Bash(apt *)", "Bash(systemctl *)", "Bash(docker *)", ...
]
```

**这些是不带 `ssh` 前缀的命令。** 在服务器工程目录下，不带前缀就意味着 AI 跑错机器了（操作的是基地容器而不是服务器），所以无条件拒绝。带前缀的写法 `ssh prod-web apt ...` 不匹配这些规则，不受影响。

这把「跑错机器」从「你能看见弹窗」变成「根本执行不了」。

### 想少弹一点

往同一个文件的 `allow` 里加常用的只读命令：

```json
"allow": [
  "Bash(ssh prod-web cat *)",
  "Bash(ssh prod-web systemctl status *)",
  "Bash(ssh prod-web journalctl *)"
]
```

改完要**重开会话**才生效。

### ⚠️ 一条铁律

**`allow` 里绝对不要出现通配写法**：

```json
"Bash(ssh prod-web *)"   ← 绝对不行
"Bash(*)"                ← 绝对不行
```

加了其中任何一条，AI 在这台服务器上做**任何事**都不会再问你了 —— 包括删库。这是唯一一个能让整套保护瞬间归零的操作。

### 关于 deny 规则的诚实说明

`deny` 是**前缀匹配**。它挡得住 `rm -rf /mnt/prod-web/etc`，但挡不住换个写法的同一件事：

```bash
cd /mnt/prod-web && rm -rf etc   ← 溜过去了
```

所以 `deny` 的作用是「降低手滑的概率」，**不是「保证安全」**。真正兜底的是「没被 allow 的命令都要你点确认」这条默认行为。

## 七、出问题怎么办

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 访问 `/mnt/xxx` 卡住，Ctrl-C 也停不下来 | 网络中断导致挂载变「僵尸」 | 面板上点「卸载」再点「挂载」 |
| 容器重启后挂载没了 | 挂载不会自动恢复（按需挂载，设计如此） | 面板上点「挂载」 |
| 挂载报 `fuse: device not found` | 容器没有 FUSE 权限 | 回到第二节第 2 步，`docker compose up -d --force-recreate` |
| 面板顶部提示「没有 sshfs」 | 当前环境不支持挂载（比如在 Mac 上原生跑） | 正常现象，以「仅命令」模式使用；要挂载就在容器里用 AI Studio |
| 接入时第 2 步失败 | 密码错，或服务器禁用了密码登录 | 看面板给的具体提示；后者需要先手工把公钥装进服务器 |
| AI 执行命令特别慢（每条好几百毫秒） | 连接复用没生效 | 容器里 `ls ~/.ai-studio/ssh/cm/` 看有没有 socket 文件 |
| AI 直接跑 `apt install` 没加 ssh 前缀 | 它跑错机器了 | 会被 deny 规则直接拒绝。反复出现的话在备注里补一条更醒目的提醒 |
| 改了 `settings.json` 但还在弹窗 | 会话没重开 | 关掉会话重新建一个 |
| 之前用命令行 `add-server` 加过的机器不见了 | 面板首次打开会自动导入 | 打开面板看是否出现「已导入 N 台」提示；没有的话手工在面板里重新添加一次 |

## 八、文件都在哪

### 每台服务器一个工作目录

`~/servers/<名字>/`：

| 文件 | 作用 | 你要改吗 |
|---|---|---|
| `CLAUDE.md` | 告诉 AI 这台机器怎么操作 | **不要手改** —— 面板会重新生成覆盖它。要补内容请改面板里的「备注」 |
| `.claude/settings.json` | 权限规则 | 按需往 `allow` 里加只读命令 |
| `.git/` | 让 AI Studio 认出这是个工程 | 不用管 |

这个目录也可以放这台机器的运维笔记、部署脚本、配置备份 —— 它是个 git 仓库，随手 commit 就有历史。

### 其他位置

| 路径 | 作用 |
|---|---|
| `~/.ai-studio/ssh/config` | 所有服务器的连接配置，**由面板自动生成，不要手工编辑** |
| `~/.ai-studio/ssh/id_ed25519` | 私钥，所有服务器共用一把 |
| `~/.ai-studio/ssh/cm/` | 连接复用的 socket，自动生成，可以随时删 |
| `/mnt/<名字>/` | 挂载点，映射服务器的根目录 |

> `~/.ai-studio/ssh/config` 的最后一行是 `Include ~/.ssh/config`，所以你自己在 `~/.ssh/config` 里配的主机（比如跳板机）照常可用，两边不冲突。
>
> 你也可以在终端里直接用这些别名：`ssh -F ~/.ai-studio/ssh/config prod-web`

### 容器重建会丢东西吗

不会。`~/servers`、`~/.ai-studio`、`~/.ssh` 都在 Docker 命名卷里（`servers-data`、`ai-studio-data`、`ssh-data`），容器重建、镜像升级都不受影响。只有 `/mnt/` 下的挂载是临时的，在面板上重新挂一下就回来了。
